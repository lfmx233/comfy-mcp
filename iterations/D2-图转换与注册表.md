## 关键决定

1. **widget 值不用贪心跳过，用按类型对齐的 DP。**
   UI 的 `widgets_values` 是位置数组，但比 API 的 widget 槽多出「隐藏的前端控件」：`KSampler` 7 个值对 6 个槽（多 `control_after_generate`）、`CLIPTextEncode` 多 `dynamicPrompts` 开关、`LoadImage` 多上传按钮值，而 `CLIPTextEncodeSDXL` 的**两个** toggle 都排在数组末尾（不是紧跟各自输入）。
   最初按「flagged 输入后面跳一个值」的贪心实现，在 SDXL 与自定义节点上直接错位（`UltimateSDUpscale` 的 `steps` 拿到了 `"dpmpp_2m"`）。
   改成 `_align_widgets`：`extras = len(values) - len(slots)`，在 `(slot, value)` 上做记忆化搜索，转移只有「assign（值类型对得上）」与「skip（花掉一次 extras）」，skip 成本 `1.0 + (n - index) / (n + 1)` —— 越靠后的值越便宜，于是优先丢末尾的隐藏控件，也把 `LoadImage ["example.png","image"]` 这种两个字符串都合法的平局断到正确的那个。
   全不可行时抛 `GRAPH_WIDGET_MISMATCH` 并说出是哪个节点：**宁可显式失败，也不静默错位**（错位的图会被 ComfyUI 接受，然后产出离谱结果，比报错难查一百倍）。

2. **模型缺失只在校验期报，转换期不管。**
   转换期做值类型校验时顺手判了 combo 成员，结果「本机没装某个 ckpt」被报成 `GRAPH_WIDGET_MISMATCH`，和「自定义节点顺序不同」混成一个错。
   拆开：`_kind_ok`（转换期）只判断「是不是标量」，combo 成员判断留给 `validate_prompt` 出 `MODEL_MISSING`，并提示本机可用的前 5 个。两类错对应两种修法，混在一起 Agent 会改错东西。

3. **哈希只覆盖图本身，不含参数。**
   `prompt_hash` = 规范化 JSON（`sort_keys` + 紧凑分隔符）的 sha256，排除 `_meta` 与节点顺序。意义是：`graph_hash` 回答「这份拓扑是哪一个」，参数值另有记录。D4 的幂等键才是 `sha256(graph_hash + 解析后的 params)`。两者不能混：混了之后改一句 prompt 就换了「工作流哈希」，Manifest 对不上账。

4. **sidecar 里路径写错要在启动时炸，不是运行时。**
   `load_workflow` 会把 `3.inputs.seed` 这种路径在图里走一遍，校验节点存在、字段存在、类型匹配。代价是加工作流要写 yaml；收益是「注册过的」这件事有真实含义 —— 一个路径写错的 yaml 会让 server 起不来，而不是让某次夜间任务静默用了默认值。

5. **参数 fan-out 用 `paths`，不是写两遍。**
   SDXL 工作流的 prompt 要同时写 `3.inputs.text_g`、`3.inputs.text_l`、`10.inputs.text`，width 要写 7 处（base/refiner 的 `width` 与 `target_width`）。若在 sidecar 里声明成三个参数，Agent 只要漏一个就得到一张尺寸不一致的图。`paths` 让「一个语义参数」对「多个物理位置」，`resolve_params` 校验一次、`apply_params` 写多处。

## 踩坑

1. **`ValueError: dictionary update sequence element #0 has length 6; 2 is required`**
   `object_info` 的 `input.required` 里既有 `["INT", {...}]` 也有 `[["a","b"], {...}]`（combo）。我先把 `required` 和 `optional` 用 `dict()` 拼起来做查表，遇到 combo 的首元素是 list 就炸。
   修法：`_input_sections` 返回 `(name, declared)` 的**原始** declared 列表，不强转 dict。

2. **`object_info.input_order` 不是 `widgets_values` 的顺序。**
   `KSampler` 的 `input_order` 是 `[model, seed, steps, cfg, sampler_name, scheduler, positive, negative, latent_image, denoise]`，而 UI 的值顺序跟着界面布局走。对齐必须用 UI `node.inputs` 的顺序（哪个输入带 `widget` 键就是 widget 槽），`input_order` 只能用来查 spec。一开始按 `input_order` 对齐，seed 拿到了 40。

3. **`UpscaleModelLoader` 的 combo 选项在本机是空数组。**
   `comfy_options = []`（一个放大模型都没装）。这种「合法但空」的 combo 既不能当类型错，也不能当成员错：转换期按标量放行，校验期报 `MODEL_MISSING` 并说明「目标实例的 models 目录里没有这类文件」。

4. **`Reroute` / `PrimitiveNode` 不在 `/object_info` 里。**
   它们是纯前端节点，查 spec 必然 `NODE_MISSING`。必须先消除再校验：`Reroute` 透传（`_resolve_link` 递归，深度上限 64 防环），`PrimitiveNode` 取 `widgets_values[0]` 变成字面量。图片放大那个工作流有 2 个 Reroute，不处理就整张图转不出来。

5. **muted 和 bypass 是两回事。**
   `mode=2`（muted）的节点应当整条丢弃并记 `dropped`；`mode=4`（bypass）的节点上游会被「短路」，静默丢弃会让下游拿到错的输入，所以直接抛 `GRAPH_BYPASSED_NODE`，要求先在图里取消 bypass。

6. **中文文件名在 PowerShell 里是乱码，但测试不受影响。**
   测试断言里出现 `屏幕截图 2024-05-08 234559.png` 这样的默认值。控制台输出乱码是因为代码页，不是数据坏了；跑测试前 `$env:PYTHONIOENCODING="utf-8"` 即可。

7. **`ruff` 的 E501 逼出一个好重构。**
   校验代码里 `f"node {node_id}.{name}: ..."` 重复 8 次且都超 100 列。改成循环开头算一次 `where = f"node {node_id}.{name}"`，8 处全用 `{where}`。（顺手被 `replace_all` 把 `where` 自己的定义也替换成 `where = f"{where}"`，`ruff` 报 `F821 Undefined name` + 6 个测试 `UnboundLocalError`，好笑但一秒能定位。）

## 遗留

- `UpscaleModelLoader` 相关的「图片放大」工作流没有登记（本机 0 个放大模型，登记了也只能报 `MODEL_MISSING`）。等工作流里出现真实需求再加。
- `graph.py` 对 `Note`/`MarkdownNote` 只丢弃不校验内容；如果将来要「注释当默认参数说明」，需要另设字段。
- 自定义节点的 widget 顺序与 `object_info` 不一致时，现在是「类型能对齐就放过，对不齐就报错」。真正的根治是读 `/object_info` 的 `input_order` + 前端 `control_after_generate` 声明，但那要跟一条 ComfyUI 前端的内部约定，先不做。
