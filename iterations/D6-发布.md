## 关键决定

1. **D6 只做到「能发」，不做到「发了」。** `twine upload` 要 PyPI API token，`mcp-publisher publish` 要 GitHub OAuth 登录态。凭据不该交给 Agent 代持，所以 D6 的验收改成「产物 + 命令 + 文档」，另开 D7 记上线。代价是简历上暂时只能说「准备了发布」，不能说「发布了」——但说了却没发出去更糟。
2. **Pillow 从必需依赖降成 extra。** `resources.py` 缺 Pillow 时本来就降级成原图直发，尺寸解析是手写文件头。把它写在 `dependencies` 里等于给所有用户装一个只在缩略时才用的包；放 `preview` extra、同时列进 `dev`，测试和 demo 照旧能用。
3. **license 用 PEP 639 表达式，顺手删掉 License classifier。** `license = "MIT"` + `license-files = ["LICENSE"]` 让 wheel 里真的带上 LICENSE 文件，METADATA 出 `License-Expression`；旧的 `License :: OSI Approved :: MIT License` classifier 和它重复，新版打包规范把这类 classifier 标成 deprecated，留着只是噪音。
4. **清单按 `2025-12-11` 的 schema 写，不追最新。** `static.modelcontextprotocol.io` 上试到 `2026-03-01` 就是 404，最新可用的是 `2025-12-11`。清单里写死 `$schema` URL，读者能自己拉下来验。
5. **版本留 `0.1.0.dev0`。** 还没上传，写 `0.1.0` 就是撒谎。PEP 440 认它是 dev 版，`pip install comfy-mcp` 默认跳过，要 `--pre`——这个坑写在 RELEASE.md 第 3 节，附带「改三处变正式版」的清单。
6. **`test_release.py` 做交叉校验，不只做字段存在性。** 三处版本号（`pyproject` / `__init__` / `server.json`）必须一致；清单里广告的每个 `environmentVariables` 必须能在 `config.py` 里 grep 到。广告一个代码根本不读的变量，比少写一个更糟。
7. **demo 拼图换 absolute URL。** `![demo](demo/contact-sheet.jpg)` 在 GitHub 上好好的，PyPI 的包页面渲染 README 时没有仓库上下文，图直接碎。改成 `https://github.com/lfmx233/comfy-mcp/raw/main/demo/contact-sheet.jpg`，两边都能显示。

## 踩坑

**1. 依赖串里塞注释，是无效 requirement。** 原 `pyproject.toml` 写着：

```toml
"pillow>=10.0  # optional at runtime: previews fall back to the original bytes without it",
```

TOML 里 `#` 在字符串内不是注释，这一整串会被当成 requirement 去解析，属于「看起来能读、实际是脏数据」。改法是把注释挪到数组外面，顺手把这行换成 extra。

**2. Registry 的 `description` 上限 100 字符。** 第一版 128 字符，schema 直接拒：

```text
jsonschema.exceptions.ValidationError: 'Run whitelisted ComfyUI workflows from an agent: parameter whitelist,
weighted progress over websocket, timeouts that interrupt, and a replayable manifest per run.' is too long
Failed validating 'maxLength' in schema['properties']['description']: ... 'maxLength': 100
```

压到 89 字符才过。清单里的长度限制是硬的，别在那儿写产品简介。

**3. PowerShell 里 `2>&1` 会把 `build` 的成功也变成 exit 1。** 命令是 `.venv\Scripts\python.exe -m build --no-isolation --outdir dist 2>&1`，产物两个都出来了，job 的退出码却是 1：

```text
.\.venv\Scripts\python.exe : * Getting build dependencies for sdist...
+ CategoryInfo : NotSpecified: (* Getting build...es for sdist...:String) [], RemoteException
+ FullyQualifiedErrorId : NativeCommandError
```

`build` 把进度写在 stderr，`2>&1` 一合并，PowerShell 就把 stderr 当错误记录，最后 `$LASTEXITCODE` 被覆盖成 1。看产物、别只看退出码；要在脚本里判断，就用 `cmd /c` 或者干脆不合并 stderr。

**4. 前台跑 pip 装包，5 分钟等不回来；丢后台 45 秒装完。** 同一个镜像、同一条命令，前台两次都撞上执行超时，连重定向的日志文件都没生成；改成后台 job 读输出，`build 1.6.1` + `twine 7.0.0` + `hatchling 1.33.0` 一次装完。没去深究 PowerShell 的缓冲行为，记一条操作习惯：装包一律丢后台，用 job 输出收尾。
