# 版本迭代记录

每个里程碑一份记录，命名 `D<编号>-<主题>.md`。写这份东西的目的不是给简历看，是为了三件事：

1. **自己回看**：三天后忘了为什么这么设计时，能查到当时的判断依据；
2. **面试能讲**：踩过的坑与取舍，比「我做了个 MCP server」有信息量；
3. **可追溯**：每份记录对应一个 commit，出问题能定位到是哪次改动引入的。

## 模板

```markdown
# D<n> · <主题>（<日期>）

## 目标
来自 docs/PLAN.md 的验收标准，原文抄一遍。

## 交付物
| 文件 | 行数 | 作用 |

## 验收结果
命令 + 实际输出（数字要真）。

## 关键决定
每条写「选了什么 / 为什么不选另一个 / 代价是什么」。

## 踩坑
错误信息原文 + 根因 + 解法。错误信息必须原样保留，以后能 grep。

## 遗留
明确没做的事，以及为什么可以先不做。

## 下一步
下一份记录要解决的问题。
```
