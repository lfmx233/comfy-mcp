## 关键决定

1. **工具返回 `CallToolResult`，不返回 dict。**
   MCP 一条消息里想同时给「JSON 文本 + 一张图 + N 个资源链接」，dict 做不到。SDK 2.3.0 的 `convert_result` 对注解是 `CallToolResult` 的函数**原样透传**，并且不为它生成 `outputSchema`——这意味着 `structuredContent` 仍是那份 JSON，客户端行为不变。
   代价：这个工具脱离了「返回值即 schema」的自动推断，payload 字段要在 `_run_result` 里手工保证稳定。

2. **manifest 一条 job 一个文件，不引 SQLite。**
   单用户、写入频率 = 出图频率，读放大只在启动那一次（最多 100 条）。`runs/<job_id>.json` 的好处是 `cat` 就能看、`git diff` 友好、坏一条不连累别人。
   代价：没有查询能力，`comfy_job` 只能按 job_id / prompt_id 精确查。

3. **尺寸自己解析，不把 Pillow 变成硬依赖。**
   `/history` 不返回宽高，唯一可靠来源是图片字节。PNG 的 IHDR、JPEG 的 SOF 段、GIF 的 LSD、WebP 的 VP8X/VP8L/VP8、BMP 的 DIB 头，都在 24 字节内。手写解析器 60 行，装不装 Pillow 都能报尺寸；Pillow 只负责重编码，缺了就走「原图直发」。

4. **模型 sha256 必须缓存，而且缓存按 `size + mtime_ns`。**
   一次运行可能涉及 2 个几 GB 的 checkpoint，每次重算等于每次多读 8GB。`checksums.json` 以绝对路径为键，命不中才读盘；文件被替换（size 变）或被原地改写（mtime 变）都会自动失效。
   代价：挪动模型目录会让缓存全部失效一次，可接受。

5. **失败不进幂等表。**
   `find_by_idempotency` 对 `failed`/`timeout`/`canceled` 直接返回 `None`。理由：idempotency key 的语义是「这次请求已经做成了」，OOM 和超时是**没做成**，缓存它们等于把错误也缓存住，重试永远拿到同一个旧错误。

6. **幂等命中也要重新取图。**
   这是本里程碑唯一一个"设计时没想到、真机跑第二次才发现"的问题：参数相同、命中旧 job，直接返回旧 endpoint 的 JSON——**没有首图**。可是调用方要的就是同一张图。改为命中后仍用 `ComfyClient` 取一次首图（失败只 warning，不影响返回）。

## 踩坑

1. **4 个 D3 测试突然变红，原因不在代码在磁盘。**
   ```text
   FAILED tests/test_server.py::test_run_is_idempotent_for_same_params
   FAILED tests/test_server.py::test_run_maps_generic_execution_failure
   FAILED tests/test_server.py::test_run_timeout_keeps_job_id_and_interrupts
   FAILED tests/test_server.py::test_queue_full_is_retryable
   ```
   根因：`App` 启动时会 `_recover()` 扫 `runs/`，而测试共用 `tests/runs`——上一个测试留下的 job 让下一个测试的"新任务"命中幂等复用，拿到的根本不是这次跑的结果。「持久化一旦上线，测试之间就不再隔离」。解法：autouse fixture 用 `monkeypatch` 把模块级 `RUNS_DIR` 指到 `tmp_path`。

2. **512×512 的图不会缩放，于是缩略图 = 原图。**
   ```text
   [fail] the inline preview is smaller than the original — 373196 < 373196 bytes
   ```
   `preview()` 原本只有一条规则「长边 > max_edge 才重编码」，512 正好等于上限，直接返回原图 373KB。补第二条规则：**文件本身 > 48KB 就重编码**，同一张图变 32KB。再补一条保险：重编码后反而更大就退回原图。

3. **测试"重编码不会变大"用了纯色图，反而更小。**
   第一版用 `_jpeg(64, 64)`（纯色 q75）当输入、`quality=95` 重编码，结果 Pillow 压得比原图还小，断言失败。换成噪声图 q30 → q95 才稳定变大。

4. **`read_resource` 拿不到原始 `ValueError`。**
   SDK 把模板资源抛出的异常包成 `"Error creating resource from template ... comfy://output/deadbeef/0"`，`pytest.raises(match="...")` 只能匹配 URI 本身，匹配不到自己写的报错文案。

5. **中文路径下 `pip install` 的老问题没再踩**，但记得 `COMFY_MCP_MODELS_DIR` 是 Windows 路径，yaml/环境变量里要双反斜杠或正斜杠。

## 遗留

1. `comfy_job` 只能查内存 + 启动时加载的最近 100 条，更老的 job 需要直接读 `runs/`。
2. 只取前 8 张输出算尺寸（远端实例的带宽考虑），第 9 张之后 `width/height` 仍是 `null`。
3. 缩略图用 JPEG q80，没有按内容自适应（线稿类图会有轻微振铃）。
4. `checksums.json` 不清理已删除模型的条目，只增不减。
5. 幂等窗口仍是「进程内 600 秒 + 落盘记录」，跨重启的复用依赖 `runs/` 里的记录仍在。
